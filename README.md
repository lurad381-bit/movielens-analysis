# Анализ MovieLens на чистом Python с тестами

Это командный проект с трека Data Science в Школе 21, нас было трое (логины в Школе 21): marlenel (это я, был тимлидом), hestlren и melbamin. Нужно было написать модуль для анализа датасета фильмов MovieLens без pandas и NumPy, то есть на обычных структурах данных Python, и покрыть его тестами.

В модуле `movielens_analysis.py` четыре класса под разные файлы датасета:
- `Ratings` - оценки: распределения по годам и по значениям, топ фильмов по средней и медианной оценке, самые "спорные" фильмы и то же самое по пользователям;
- `Movies` - фильмы: распределение по годам и жанрам, фильмы с наибольшим числом жанров;
- `Tags` - теги: самые частые, самые длинные, поиск по слову;
- `Links` - данные с IMDb: режиссёр, бюджет, сборы и длительность фильмов.

**Как распределяли работу.** Я разбил модуль на три части примерно одинаковой сложности. Один человек брал `Ratings`, там вложенные классы и наследование (`Users` наследуется от `Movies` и считает те же методы, но уже по пользователям). Второй брал `Links`, там 7 методов, и 6 из них зависят от парсинга IMDb в `get_imdb`, поэтому начинать нужно было именно с него. Третий брал `Movies` и `Tags`, это два независимых класса, 12 методов без внешних зависимостей. Каждый писал тесты на свои классы, потом собрали общий модуль и вместе сделали отчёт. `Ratings`, `Movies` и `Tags` писали hestlren и melbamin.

**Моя часть.** Кроме распределения задач и координации команды, я делал класс `Links`. `get_imdb` достаёт со страниц IMDb режиссёра, бюджет, сборы и длительность через requests и BeautifulSoup, а на его основе считаются топ режиссёров, средний бюджет по режиссёрам, самые дорогие и самые прибыльные фильмы, самые длинные фильмы и стоимость минуты фильма. Напрямую парсить IMDb оказалось проблемно из-за защиты от ботов, поэтому модуль сначала смотрит в заранее собранный файл `imdb_cache.json` (там данные по 1000 фильмам), а то, что пришлось скачать, запоминает в памяти, чтобы не запрашивать повторно. Сам файл кэша в репозиторий не входит.

Тесты для `Links` тоже мои, это 6 из 28 тестов модуля. Проверял типы и сортировку результатов, обработку ошибок (несуществующий файл, обрыв соединения), а прибыль и стоимость минуты сверял со значениями, которые посчитал вручную. Запросы к IMDb в тестах подменяются заглушкой, чтобы тесты не зависели от сети.

Отчёт `movielens_report.ipynb` делали вместе, там используются все методы модуля на реальных данных, и для каждого замерено время через `%timeit`. По условию задачи модуль работает с первыми 1000 записей: читает первые 1000 фильмов, тегов и ссылок, а оценки берёт только для этих фильмов.

**Как запустить:** скачать уменьшенную версию датасета MovieLens (например, [MovieLens Latest Small](https://grouplens.org/datasets/movielens/latest/)) и положить `movies.csv`, `ratings.csv`, `tags.csv`, `links.csv` рядом с модулем. Дальше `pip install -r requirements.txt`, тесты запускаются через `pytest movielens_analysis.py` (тестам для фильмов, тегов и ссылок нужны файлы датасета), отчёт в `movielens_report.ipynb`. Данные и кэш IMDb в репозиторий не входят.

**Стек:** Python, pytest, requests, BeautifulSoup, Jupyter
