# Анализ MovieLens на чистом Python с тестами

Это командный проект с трека Data Science в Школе 21, нас было трое (логины в Школе 21): marlenel (это я, был тимлидом), hestlren и melbamin. Нужно было написать модуль для анализа датасета фильмов MovieLens без pandas и NumPy, то есть на обычных структурах данных Python, и покрыть его тестами.

В модуле `movielens_analysis.py` четыре класса под разные файлы датасета:
- `Ratings` - оценки: распределения по годам и по значениям, топ фильмов по средней и медианной оценке, самые "спорные" фильмы и то же самое по пользователям;
- `Movies` - фильмы: распределение по годам и жанрам, фильмы с наибольшим числом жанров;
- `Tags` - теги: самые частые, самые длинные, поиск по слову;
- `Links` - данные о фильмах (режиссёр, бюджет, сборы и длительность), по заданию с IMDb, а по факту с TMDb, про это ниже.

**Как распределяли работу.** Я разбил модуль на три части примерно одинаковой сложности. Один человек брал `Ratings`, там вложенные классы и наследование (`Users` наследуется от `Movies` и считает те же методы, но уже по пользователям). Второй брал `Links`, там 7 методов, и 6 из них зависят от того, как `get_imdb` достанет данные о фильмах, поэтому начинать нужно было именно с него. Третий брал `Movies` и `Tags`, это два независимых класса, 12 методов без внешних зависимостей. Каждый писал тесты на свои классы, потом собрали общий модуль и вместе сделали отчёт. В итоге `Ratings` и тесты к нему писал melbamin, а `Movies` и `Tags` писал hestlren.

**Моя часть.** Кроме распределения задач и координации команды, я делал класс `Links`. `get_imdb` достаёт для фильмов режиссёра, бюджет, сборы и длительность, а на его основе считаются топ режиссёров, средний бюджет по режиссёрам, самые дорогие и самые прибыльные фильмы, самые длинные фильмы и стоимость минуты фильма. По заданию данные надо было парсить с IMDb, но у IMDb стоит JS-капча от ботов, и пройти её теми библиотеками, которые были разрешены (requests и BeautifulSoup), у меня не получилось. Поэтому данные по 1000 фильмам я спарсил с [TMDb](https://www.themoviedb.org/) и сохранил в файл `imdb_cache.json`, он лежит в репозитории, и модуль сначала берёт данные из него. Для части фильмов на TMDb просто нет данных, у 287 фильмов из 1000 нет бюджета, а у 184 нет сборов, поэтому они не попадают в расчёты по деньгам. Код, который ходит на страницы IMDb, в модуле остался, но без кэша IMDb обычно отдаёт капчу и данные получаются пустыми.

Тесты для `Links` тоже мои, это 6 из 28 тестов модуля. Проверял типы и сортировку результатов, обработку ошибок (несуществующий файл, обрыв соединения), а прибыль и стоимость минуты сверял со значениями, которые посчитал вручную. Запросы к сайту в тестах подменяются заглушкой, чтобы тесты не зависели от сети.

Отчёт `movielens_report.ipynb` делали вместе, там используются все методы модуля на реальных данных, и для каждого замерено время через `%timeit`. По условию задачи модуль работает с первыми 1000 записей: читает первые 1000 фильмов, тегов и ссылок, а оценки берёт только для этих фильмов.

**Как запустить:** скачать уменьшенную версию датасета MovieLens (например, [MovieLens Latest Small](https://grouplens.org/datasets/movielens/latest/)) и положить `movies.csv`, `ratings.csv`, `tags.csv`, `links.csv` рядом с модулем, там же лежит `imdb_cache.json`. Дальше `pip install -r requirements.txt`, тесты запускаются через `pytest movielens_analysis.py` (тестам для фильмов, тегов и ссылок нужны файлы датасета), отчёт в `movielens_report.ipynb`. Сам датасет MovieLens в репозиторий не входит, а данные о фильмах в `imdb_cache.json` взяты с TMDb.

**Стек:** Python, pytest, requests, BeautifulSoup, Jupyter
